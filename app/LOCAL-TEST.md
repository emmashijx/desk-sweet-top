# Home Sweet Home · 显示器本地测试

## 编辑布局

首次打开时会进入编辑器。从桌面按 Command+E 可再次打开。选择「生成空房间」以现有墙纸、护墙板和地板创建背景，或从本机导入图片。「载入原始布局」可以添加整套示例家具。

在组件库中点击家具即可添加。拖动画布上的家具可以移动，底部可调整大小、层级或移除。「保存并返回桌面」会在本机保存布局，应用下次启动时会自动载入。重新生成或导入背景会替换背景，已添加的家具位置会保留。

编辑器顶部的布置菜单可以打开已保存的版本、重命名或新建空白布置。用「另存为新布置…」把当前背景和家具保存成独立版本。桌面可从「窗口 → 房间布置」切换，下次启动会回到上次使用的版本。更新前保存的布局会自动载入为「初始布置」。

## 进入房间

双击项目中的 `output/local-test/HomeSweetHome.app`，或在项目根目录的终端执行：

```sh
open "output/local-test/HomeSweetHome.app"
```

房间是独立的 macOS 应用，并非替换系统桌面；目前只实现了显示器功能。点击黑灰色显示器或按回车键，屏幕内出现 Chrome、Safari 两个入口。先选半屏（默认）或全屏，再选浏览器。Esc 或「取消」关闭选择器；按 Command+Tab 回到房间；Command+Q 退出房间而不会退出浏览器。绿色窗口按钮或 Control+Command+F 可以切换房间全屏。

界面自动跟随 macOS 首选语言，当前提供英文、简体中文和繁体中文，其他语言回退为英文。鼠标点击时不显示系统焦点色框；主动使用 Tab 键时仅用文字下划线标示焦点，按回车或空格确认。

显示器排版使用原生系统字体与独立角色字号：标题 17、Chrome/Safari 主操作 15.5、窗口模式 12、取消与反馈 11.5（以 258×165 基准屏幕为例）。文字根据显示器的实际尺寸进行适配，错误反馈按语义换行；极小家具仍可保持内容不溢出，但建议保留正常显示器大小以便舒适阅读。

显示器选择界面采用浅雾蓝背景、奶油白浏览器列表及深灰蓝文字。半屏/全屏为上方等宽单选项，圆点区分选中状态；Chrome/Safari 纵向排列，底部保留稳定的启动或错误提示区域。无系统焦点色框。

全屏及任意窗口尺寸下，墙纸、护墙板、地板自适应铺满内容区域，不留灰边；家具及其点击区域保持统一等比缩放，墙地接缝与家具接触位置保持对齐。

本测试版本使用 `assets/design/v3/layers-v3-22-refined` 的 27 个独立图层。透明边缘重新精修，保留原始家具像素与自然软阴影，原 V3.22 素材不被覆盖。

## 真实环境验收

| 测试场景 | 应看到的结果 |
| --- | --- |
| Chrome 已打开一个有多个标签页的窗口 | 点击显示器 → 半屏 → Chrome，激活已有浏览器窗口，保留标签页与登录状态。 |
| Safari 已打开窗口 | 点击显示器 → 全屏 → Safari，激活已有窗口并使用原生全屏。 |
| 浏览器运行但没有窗口（在保存工作后自行关闭窗口） | 重新选择该浏览器，应打开一个普通新窗口及默认页面。 |
| 浏览器已退出且配置了恢复上次会话 | 正常启动，由浏览器自身恢复原窗口和标签页，不另外重建历史。 |
| 不允许窗口控制 | 浏览器仍正常打开；如需半屏或全屏，可以手动使用原生窗口按钮。 |
| 点击其余家具或 Esc | 其余家具暂不响应，取消选择不会打开浏览器。 |

## 首次使用授权

- macOS 可能询问是否允许 Home Sweet Home 控制 Chrome 或 Safari（系统设置 → 隐私与安全性 → 自动化）。本应用只查询窗口数量，在明确没有窗口时创建普通新窗口。若未授权，且没有看到窗口，请手动按 Command+N。应用不读取标签页 URL、浏览历史、Cookie 或本地浏览器配置。
- 自动半屏及全屏需要「系统设置 → 隐私与安全性 → 辅助功能」授权 Home Sweet Home。半屏是当前屏幕可用区域的右半侧，全屏使用浏览器原生全屏。授权后可以再次点击显示器验证。若权限不可用，仍会启动浏览器，且不会反复主动请求辅助功能权限。
- 浏览器完全退出时，要能恢复旧会话，需要浏览器自身启用相应恢复设置。本应用不会修改浏览器设置。重建测试应用后，系统可能要求重新授权。

自动测试使用模拟浏览器驱动，不启动、关闭或修改真实 Chrome/Safari 窗口。截图保存在 `output/local-test`，分别为待机、选择界面和全尺寸选择界面。真实浏览器权限及窗口行为由上述手动测试确认。
