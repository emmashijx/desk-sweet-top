# Design

## Context

当前项目只有视觉素材和分层导出脚本，尚无应用源码。V3.22 提供 1557×1010 的 27 张同画布透明图层、边界清单及可编辑 PSD；Chrome 与 Safari 均已安装在本机。此设计为首个组件建立可扩展但小范围的原生运行时。

## Goals / Non-Goals

**Goals:**

- 复用已确认的房间素材，以独立层和配置建立首个可操作的原生测试窗口。
- 显示器选择器留在实际屏幕范围内；真正的浏览操作由用户已安装的原生浏览器承载。
- 保护浏览器现有窗口与标签页，支持半屏/全屏，权限不足时可解释地退化。

**Non-Goals:**

- 不实现系统桌面替换、后台常驻、登录启动、全局快捷键、家具编辑器或其他物件功能。保留可配置边界，为后续变更准备。
- 不内嵌 WebView、模拟浏览器、读取用户的历史记录，或通过浏览器内部配置文件重建会话。
- 不修改 V3.22 设计资产，不写死成一张扁平背景。

## Decisions

1. **原生 Swift/AppKit 或 SwiftUI。** 本机已有命令行 Swift 工具链，使用无需额外第三方依赖的 Swift 项目与 `.app` 打包脚本；相比网页原型，能够直接调用系统应用启动与正常窗口能力。采用可执行构建脚本并将资源随应用打包，保证可以从 Finder 或终端打开。
2. **统一布局与交互坐标。** 从现有 manifest 生成独立配置，记录每个素材、源边界、目标坐标、比例、层级、可见性及可交互角色。家具按统一等比变换完整渲染，显示器屏幕选择器和 hit area 使用同一变换；墙纸、护墙板和地板作为结构层延伸至窗口边缘，保留等比变换后的墙地接缝高度，避免全屏出现灰边。书桌及其他图层暂不触发。使用现有全画布 PNG 的透明信息及源边界支持后续移动，不直接拼平成一张效果图。
3. **显示器状态机。** `idle → choosing → launching → idle`；失败回到选择状态并展示行内提示。待机黑灰屏为已有独立素材，点击开启选择器；自绘简洁浏览器标记通过文字辅助识别，保留两个入口，半屏/全屏作为当前选择偏好（默认半屏），Esc 取消、键盘焦点可操作。不在房间中显示 macOS 图标或工具栏。
4. **真实浏览器生命周期。** 使用 `NSWorkspace` 按 bundle id 定位和启动（Chrome: `com.google.Chrome`，Safari: `com.apple.Safari`）；已运行时优先激活。根据浏览器允许的公开 Apple Events / AppleScript 窗口能力，判断是否已有窗口；等待正常启动和浏览器自身会话恢复完成，只有明确无窗口时才请求创建普通新窗口。不会读取、记录或重建标签页 URL。若查询权限被拒绝，仍正常激活应用；在用户看到无窗口时提供明确的新建窗口操作指引，不能猜测并额外创建。
5. **窗口布局独立于启动。** 半屏选择基于当前屏幕的可用区域定位前台窗口（右半屏，左侧可保留房间或其他应用）；原生全屏使用系统公开的窗口可访问性能力，在可信授权后调整窗口，绝不强改系统设置或绕过权限。窗口控制失败时给出说明，浏览器启动成功不因其失败而回滚。用户可正常使用浏览器的自身窗口控制和 App 切换。
6. **本机验证和可测的适配层。** 浏览器查找、启动、窗口检查和窗口模式抽象为接口，以模拟适配器覆盖不同启动结果，真实手测已有窗口、无窗口、两浏览器、半屏/全屏、返回房间及拒绝授权路径。真实浏览器的已有窗口或会话只能在用户本地确认，测试不自动关闭用户的窗口或更改其数据。

## Risks / Trade-offs

- 浏览器自身的启动偏好可能不恢复已彻底关闭的会话 → 尊重其首选项并明确说明上一会话恢复依赖浏览器自身能力；不读取私人数据目录，也不强制覆盖偏好。
- macOS Automation 与 Accessibility 权限可能未授权 → 只在用户明确选择启动/窗口布局时走公开授权流程；拒绝后仍可打开真实浏览器，提供系统正常操作指引。
- 启动及恢复具有异步性 → 在有限时间内等待并重新检查窗口；不在判定不明时创建重复窗口。
- 房间图层目前是栅格提取重建 → 保持素材原样，配置与命中范围分离，避免后续组件开发重新生成整幅房间图。

## Migration Plan

无已有应用或数据迁移。构建输出放入独立的本地测试目录，保留原始设计素材与 OpenSpec 变更；删除本测试应用即可回到原状态，不改变浏览器偏好。
