# Proposal

## Why

房间外观及分层素材已达到 V3.22，用户希望开始验证真实组件交互。首个组件选择显示器，使其成为只包含 Chrome 和 Safari 的浏览器入口，直接进入已有浏览环境，无可恢复窗口时打开新页面。

## What Changes

- 创建可在本机 MacBook Air 启动的最小原生桌面测试应用，按 V3.22 独立图层与布局配置渲染房间，不以整张合成图写死交互。
- 点击显示器，在屏幕区域内显示 Chrome、Safari 两个自绘选择项；支持选择、取消与键盘操作。
- 选择浏览器后使用真实浏览器应用，优先激活已有窗口并保留标签页；应用未运行时尊重浏览器正常启动的会话恢复机制，若没有可用窗口则创建正常的新窗口和页面。
- 提供半屏/全屏窗口偏好；权限拒绝时仍可正常启动浏览器，并告知如何使用系统窗口控制完成布局。
- 返回房间时显示器恢复待机状态，保留用户既有浏览器状态。其他物件暂不接入功能，不实现通用 App 启动器。
- 提供可在本机执行的构建、启动命令与验证步骤。

## Capabilities

### New Capabilities

- `room-runtime`: 提供基于独立素材与可配置坐标的房间测试运行时。
- `monitor-browser-launcher`: 显示器浏览器选择、原生浏览器启动、窗口恢复及窗口布局反馈。

### Modified Capabilities

无。

## Impact

- 新增原生 macOS 测试应用源码、资源装配、布局配置、测试和本地启动说明。
- 复用 `assets/design/v3/layers-v3-22/png-layers` 与 `layer-manifest.json`，不修改原有设计图层。
- Chrome/Safari 的真实窗口行为依赖本机安装状态、浏览器会话恢复偏好和 macOS 的正常自动化权限。不会读取、复制或删除浏览历史、Cookie、登录态或用户数据目录。
