# Spec Delta

## Purpose

让房间里的显示器成为独立、克制的浏览器入口，保留用户已有的浏览器工作状态，同时提供真实浏览器窗口与清楚的可恢复反馈，不在房间中模拟浏览器。

## ADDED Requirements

### Requirement: 待机与浏览器选择

显示器 SHALL 默认呈现黑灰待机屏幕，点击或键盘激活后仅在屏幕内显示 Chrome 与 Safari 两个浏览器选择项，及必要的窗口模式选择和取消操作，不显示通用应用列表或系统原生桌面图标。

#### Scenario: 显示浏览器入口
- **WHEN** 用户点击显示器
- **THEN** 在显示器屏幕区域显示浅雾蓝底的浏览器选择器；上方为半屏/全屏单选模式，下方奶油白列表纵向显示 Chrome、Safari 两个自绘入口，底部保留反馈空间，房间其他家具外观不变。

#### Scenario: 取消选择
- **WHEN** 用户按 Esc 或取消
- **THEN** 显示器恢复黑灰待机，且不启动浏览器。

#### Scenario: 显示器尺寸或系统语言变化
- **WHEN** 房间内的显示器尺寸或 macOS 首选语言变化
- **THEN** 标题、浏览器主入口、窗口模式、取消与反馈保持明确的排版层级，文字和图标适配实际屏幕区域；中英文反馈按完整语义换行，不与其他控件重叠。

### Requirement: 优先恢复浏览器环境

选择浏览器后系统 SHALL 启动或激活对应真实 macOS 浏览器。若存在可用窗口，应优先使用已有窗口，保留其标签页与登录状态；正常启动时尊重浏览器自身的上次会话恢复机制，不强制打开新标签页或重建用户配置。

#### Scenario: 存在浏览器窗口
- **WHEN** 所选浏览器已有可用窗口与标签页
- **THEN** 激活其中最近前台窗口，不额外创建窗口或标签页。

#### Scenario: 浏览器未运行且有可恢复会话
- **WHEN** 用户选择未运行的浏览器且其本身正常启动会恢复上次会话
- **THEN** 正常启动并保留浏览器恢复的窗口与标签页，不覆盖恢复结果。

### Requirement: 无窗口时打开新页面

当浏览器正常启动后没有可用窗口或恢复结果，系统 SHALL 打开该浏览器的普通新窗口和默认新标签页，不进入隐私浏览模式，也不读取浏览历史来重建会话。

#### Scenario: 无既有窗口
- **WHEN** 浏览器没有可用窗口且未恢复会话
- **THEN** 正常创建一个新窗口和新页面。

### Requirement: 半屏与全屏窗口

系统 SHALL 提供半屏与全屏浏览器窗口模式；半屏使用当前屏幕可用区域内的半宽窗口，全屏使用浏览器的原生全屏状态。窗口控制需要系统授权时应透明提示；权限不可用不得阻止浏览器启动，用户仍可通过系统窗口控制完成调整。

#### Scenario: 半屏选择
- **WHEN** 用户选择半屏并启动浏览器，且窗口控制可用
- **THEN** 浏览器前台窗口使用当前屏幕可用区域的一半，纵向填满可用高度。

#### Scenario: 全屏选择
- **WHEN** 用户选择全屏并启动浏览器，且窗口控制可用
- **THEN** 浏览器前台窗口进入原生全屏状态。

#### Scenario: 系统拒绝窗口控制
- **WHEN** 用户不授予本机窗口控制权限
- **THEN** 浏览器仍被正常打开或激活，并提供使用系统窗口控件的说明，不反复请求权限。

### Requirement: 启动反馈与恢复待机

系统 SHALL 在浏览器不存在、启动失败或窗口控制失败时显示可理解的反馈并允许重试或取消；浏览器成功激活后关闭选择界面，让用户通过系统应用切换返回房间时看到原待机屏幕。

#### Scenario: Chrome 未安装
- **WHEN** 用户选择未安装的 Chrome
- **THEN** 显示未安装提示并保留 Safari 可选，不结束应用。

#### Scenario: 返回房间
- **WHEN** 用户完成启动并切回房间应用
- **THEN** 显示器呈现待机状态，不关闭或重置浏览器已有窗口与标签页。
